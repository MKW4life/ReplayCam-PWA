# ReplayCam v0.2 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Improve recording controls and deliver locally merged replay files with ZIP fallback.

**Architecture:** Preserve the static PWA and existing IndexedDB schema. Pure settings/estimation helpers drive the UI; a dedicated worker remuxes compatible segments using a pinned local Mediabunny bundle.

**Tech Stack:** JavaScript modules, MediaRecorder, IndexedDB, Worker, Mediabunny, Node test runner, esbuild for vendoring only.

**Spec:** ../specs/2026-11-05-replaycam-v02-design.md

## Global Constraints
- No video upload; all runtime assets served from this site.
- Existing saved recordings must remain usable.
- Merge limit 256 MiB; explicit ZIP fallback; no gap-repair guarantee.
- Higher resolution is a preference, actual capture settings must be shown.

## Review Focus
- Camera fallback/unknown facing must not be mislabeled.
- Audio must survive segment joins; changed codecs/rotation must reject safely.
- Unequal audio/video start times and B frames must preserve synchronization.
- Merge failure or unavailable Worker must leave originals and ZIP available.
- Service worker upgrade must not delete other projects' caches or IndexedDB.
