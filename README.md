# ReplayCam PWA v0.4.2

Windowsで開発・公開できる、iPhone向けカメラ録画アプリの初版です。静的Webアプリ、サーバーへの動画送信なし。動画結合には同梱のMediabunnyを使用します。

## 実装済み

- 初期設定 **3分 / 1080p / 60fps / マイクON**（設定は端末に保存）
- リプレイバッファ **3・5・10・15分**。MP4対応ブラウザーでは1回の連続録画を維持し、届いたフラグメントをIndexedDBへ保存して古いものを削除
- 保存ボタンで直前の指定時間を保存済み一覧へ登録。MP4連続モードでは保存時も録画を停止・再起動しない
- リプレイ区間を個別再生・保存、または動画に結合 / ZIPファイルで一括書き出し
- 通常録画モード：停止時に1本のMP4/WebMとして保存、ダウンロード
- 720p / 1080p / 1440p / 4K（2160p）の希望設定、30/60fps、音声ON/OFF
- 内カメラ（前面）/ 外カメラ（背面）の選択と、実際の使用カメラの表示
- 希望設定から容量を予想し、録画中は実測したデータ量から補正
- 1つの録画内の全区間を順番に端末内で結合し、1本の動画を出力（256MiB制限を撤廃）
- 対応する端末では「写真に保存・共有」からiOSの共有画面へ動画を渡す
- HTTPS上でPWAとしてインストール、初回読み込み後はオフライン起動を目指すService Worker
- 保存済み動画の一覧・削除・容量表示

## 重要な制限

- **iPhoneのSafariでの動作は未検証**。ブラウザによるカメラ許可、録画コーデック、保存/共有、IndexedDB容量は端末実機で検証してください。
- **4Kを含む選択した解像度・fpsを必ず達成するわけではありません。** ブラウザとiPhoneが許可する実効値はプレビュー右上に表示されます。実際のエンコードされた動画のfps/解像度はファイルでも確認してください。
- MP4リプレイは1回のMediaRecorder録画から届くフラグメントを保存する実装です。対応MP4形式がない場合のみ、従来の区間切替を伴う互換モードを使用します。「保存済み」から書き出す際、対応する区間を再圧縮せず1本のMP4/WebMに結合します。**区間の形式・音声構成・画角が一致しない場合や、空き容量・メモリ不足などで結合できない場合は、理由を表示します。自動でZIPへは切り替えません。** 元の区間は保存済みに残り、「ZIPで保存」は必要なときに明示的に選べます。 互換モードでは録画再起動時に欠落があり得ます。ZIPから取り出した動画をWindows PCの動画編集ソフト等で結合できます。ブラウザーやカメラ自体のフレーム欠落を復元することはできません。開始・終了位置はキーフレームに合わせて数秒前後することがあります。
- 通常録画は同じMediaRecorderの複数 `dataavailable` データを正しい順で連結して1本のファイルにします（独立動画を単純結合していません）。
- SafariやiOSの制限により、画面ロック・アプリ切替・電源管理で録画が中断されることがあります。録画中は画面を開いたままにしてください。
- 15分1080p/60fpsは数百MB〜1GB超になる可能性があります。iOSストレージの容量制限、バックグラウンド停止、サイトデータ削除で未書き出し動画を失う可能性があります。**保存済み一覧への登録だけでは写真アプリへの保存にはなりません。必ず動画を書き出し、写真または「ファイル」に保存したことを確認してください。**
- サーバーは動画データを受信しません。HTTPSで配信する静的ファイル以外に通信を必要としません。
- 当初の設計からPCの遠隔操作機能は**未実装**。カメラの録画・保存の検証を優先しています。

## Windowsから無料でiPhoneに導入する

### GitHub Pagesで公開（HTTPS、無料）

1. GitHubに新しい**公開リポジトリ**（例: `replaycam`）を作ります。動画はGitHubには上げません。上げるのはこのZIPに含まれるHTML/CSS/JS等だけです。
2. ZIPを展開し、中にある `index.html`・`app.js`・`sw.js`・`manifest.webmanifest`・`icons/` などを **リポジトリのルート** にアップロードします。
3. リポジトリの `Settings` → `Pages` → `Build and deployment` → `Deploy from a branch` → `main` / `/(root)` → `Save`。
4. Pagesに表示される `https://ユーザー名.github.io/replaycam/` にiPhoneの **Safari** でアクセスします。
5. Safariの共有メニューから **ホーム画面に追加**。アプリアイコンから起動して録画できます。
6. 初回表示後、通信を切って再起動できるか試してください。オフライン時のカメラ権限動作も合わせて確認します。

> GitHub Pagesに公開するWebアプリのソースは公開されます。録画データ自体はiPhoneのローカルIndexedDB内に残り、GitHubにはアップロードされません。

### 開発テスト

```bash
node --test tests/*.test.mjs
python -m http.server 8000
```

Windows上で `http://localhost:8000` を開けば画面とPCカメラのテストができます。ただし、iPhoneからWindowsの `http://192.168.x.x:8000` にアクセスしても、通常はHTTPSではないためカメラが使えません。GitHub PagesなどのHTTPSが必要です。

## 操作

- 「リプレイバッファ」を選び「録画開始」→任意の時点で「直前を保存」→「保存済み」から「開く」→「全区間を1本の動画にする」。明示的に「ZIPで保存」も選べます。
- 「通常録画」→「録画開始」→「終了して保存」→保存済み一覧から動画を1本で書き出します。
- 対応端末では結合後に「写真に保存・共有」を押し、共有画面に「ビデオを保存」があれば選択します。Safariから写真アプリに無操作で直接書き込むことはできません。共有できない形式・端末ではダウンロード操作で動画を保存します。自動ダウンロードが始まらない場合は書き出し後のリンクをタップしてください。Safariでプレビューが開く場合は共有メニューから「ファイルに保存」を選んでください。保存済み一覧は端末の写真ライブラリではありません。

## 次の開発予定

- iPhone実機でMediaRecorderのコーデック・分割保存・容量を検証
- 長時間・大容量の結合、録画区間の切り替え時の欠落の改善
- 長時間安定性、画面スリープ対策、空き容量不足の事前警告
- Windows PCのリモート画面表示・操作（別モジュール、認証/暗号化必須）

## Windowsでリプレイを1本に結合する

リプレイをZIPで書き出した後、Windows PCへ移して次の操作を行います。

1. Windowsに **FFmpeg** をインストールしてPATHを通す（初回のみ）。
2. ZIPファイルを `windows/merge_replay.bat` にドラッグ＆ドロップする。
3. 同じフォルダに結合した `.mp4` または `.webm` ファイルができます。

FFmpegの `concat` を利用して映像と音声を再エンコードせず結合します。分割録画時点の短い欠落は修復できません。コーデックやタイムスタンプの状態によっては結合できず、再エンコードが必要になる場合があります。

## v0.2.0 開発と検証

`npm ci` → `npm test`。同梱ライブラリの再生成は `npm run build:vendor`。`vendor/mediabunny.js` はMediabunny 1.65.2の固定版で、ライセンスは `vendor/mediabunny-LICENSE.txt`。実行時のCDNや動画アップロードはありません。

ブラウザーテストは `npm run test:browser`。既定はWindowsのBraveを専用のテストプロファイルで起動し、疑似カメラ・マイクを使用します。別のChromium系ブラウザーを使う場合は `REPLAYCAM_BROWSER` に実行ファイルのパスを指定します。iPhone Safari実機の検証を代替するものではありません。テスト動画はFFmpegのtestsrcとsineで生成した素材です。MP4/WebMの映像・音声・時刻・回転、無音動画、失敗時のZIP、設定保存、オフライン起動を検証します。

## サイトの共有

公開URLを他の人に共有できます。録画・保存・結合は各利用者のブラウザーで行い、利用者間で動画は共有されません。端末容量、カメラ権限、Safariの対応状況に依存する試用版として案内してください。サイトのデータを消去すると、未書き出し動画を失う可能性があります。

更新時はオンラインでページを再読み込みし、一度閉じて開き直してフッターがv0.3.1になったことを確認してください。既存の保存済み動画のデータベース構成は変更していません。

## v0.2.1 横向き録画

端末の画面回転ロックを解除し、横向きに持ってから「録画開始」を押してください。通常録画とリプレイバッファの両方に対応します。プレビューは映像全体を表示し、実際のカメラ映像の縦横比に追従します。横画面では録画・保存・停止ボタンを映像の横に配置します。

録画開始時の向きを保存済み一覧に表示します。録画中に画面の向き、またはカメラ映像の縦横が変わると、通常録画を保存して終了し、リプレイでは直前のバッファを保存して終了します。向きを合わせて録画を再開してください。端末やブラウザーが回転通知を提供しない場合は検知できないため、録画中は向きを保ってください。既存の保存済み動画や縦向き録画、動画の回転情報を保った結合処理は維持しています。

デスクトップブラウザーの疑似カメラによる横向き動画のダウンロード・音声・画面回転時の保存を自動テストしています。iPhone実機での回転、Safari固有の回転情報・撮影挙動は未検証です。更新後はページを再読み込みし、フッターのv0.3.1を確認してください。

## v0.3.0 全区間の動画出力・写真への共有・fps表示

全区間を1本の標準MP4/WebMへ順番に再構成します。映像と音声は再圧縮しません。対応ブラウザーでは専用Worker内でOPFS（ブラウザー内の一時ファイル）へ少しずつ書き込むため、動画全体のArrayBufferを用意しません。OPFSが使えない場合も小さなBlob単位で出力します。固定の256MiB制限はありませんが、端末の保存上限やメモリ上限を超える動画を保証するものではありません。結合中は元動画に加えて出力分の空き容量が必要です。

結合済みの一時ファイルは、書き出し画面を閉じた後などに猶予を置いて削除します。再読み込み時には同じタブの未解放ファイルを回収します。ブラウザーやタブの異常終了で一時データが残る場合があります。大きな動画の共有可否はOS・ブラウザー・形式に依存します。共有ボタンは完成ファイルに対する新しいタップで開き、共有画面へ渡せたことと写真への保存完了を区別します。

60fpsを選んだ場合はカメラへexact 60fpsを先に要求し、その条件が未対応なら低いfpsも許容する要求へ切り替えます。カメラ設定のfpsと、保存動画のエンコード後fpsは同じとは限りません。MP4連続リプレイでは、届いた録画データから平均fpsと最大フレーム間隔を計算して表示します。希望値とカメラ設定値を分けて表示します。H.264の低いプロファイル/レベルを固定せず、端末が選べる設定を使い、録画中は区間ごとにコーデックが切り替わらないよう形式を固定します。端末の標準カメラが60fpsに対応していても、Safariで同じ解像度・fpsが利用できる保証はありません。

256MiB超の入力、複数区間の映像・音声パケットの順序と完全性、一時ファイル削除、共有APIへ渡すファイルとタップ操作、60fps要求のフォールバックを自動テストしています。iPhone実機での写真保存・長時間高解像度録画は未検証です。

## v0.3.1 保存される画角の表示

カメラ映像そのもののサイズから表示領域を計算し、白い枠で保存対象の映像全体を示します。映像は拡大して切り抜かず、縦横比を保って収まるように表示します。余白は録画されません。録画時間・保存時間・カメラ設定は映像の外に置き、画角の端を隠さないようにしました。画面サイズやカメラ映像の縦横が変わったときも枠を更新します。

## v0.3.2 リプレイ録画の保存待ちを短縮

前の区間の保存・期限切れデータ整理が終わるのを待って次の録画を始める方式を改め、次の区間を先に開始してから保存処理を行います。メモリ使用量を抑えるため、先行する録画は1区間までです。「直前を保存」は押した時点で録画していた区間の保存を待ってから確定し、停止時も最後の区間まで処理します。録画開始・停止そのものによる欠落や、保存が1区間分の録画時間より長くかかる場合の待ち時間は残り得ます。

この変更は保存待ちによる途切れを減らすもので、Safariのカメラ取得やエンコードで60fpsを保証するものではありません。実機の約25fps・フリーズの全原因は、写真だけでは特定できていません。遅い保存処理を再現する自動テストで、保存完了前に次の録画が始まることと、保存対象区間が残ることを確認しています。

## v0.4.0 定期的な録画停止・再開を廃止

MP4形式が利用できる場合、MediaRecorderを一度だけ開始し、15秒ごとの再起動を行いません。「直前を保存」でも停止せず、requestDataでデータを要求して必要な区間が届いてから保存を確定します。ブラウザーの出力タイミングにより保存完了まで数秒かかる場合があります。通常録画は従来どおり連続録画です。

WorkerでMP4の初期化情報とmoof/mdatを分離し、フラグメントの絶対データ位置を補正して保存します。保存されたフラグメントを再結合する際も、元の連続した映像・音声時刻を保持します。バッファは直前の指定時間と、その前の再生開始可能位置を保持し、音声だけが続いて映像が停止した場合にも古いフラグメントを無制限に保持しません。

MP4連続形式に対応しないブラウザーでは互換モードの案内を表示します。ブラウザーがMP4を名乗っていてもフラグメント形式を出力しない場合は、無期限にデータを溜めずエラーを表示します。その場合は通常録画を利用してください。

実際に保存されるフレームの平均fpsと最大フレーム間隔を表示します。これはカメラ設定値ではなく、録画コンテナ内のフレーム時刻から計算した値です。端末実機での60fps達成・すべてのフリーズの解消を保証するものではありません。

検証では、15秒超の録画中・複数回の保存操作中に録画機のstartが1回、stopが0回であること、保存を遅くしても録画を継続すること、出力動画に数秒の時刻の穴を作らないこと、映像・音声・古い保存済み動画・オフライン出力を確認しています。

## v0.4.1 Safariの区間保存経路の修正

- 動画区間をBlobのままIndexedDBへ渡さず、所有するArrayBufferとして保存します。切り出し・結合したBlobの登録がWebKitで失敗する経路を回避します。
- 旧形式の保存済み動画も読み出し時にバイト列へコピーします。既存の保存データを削除・移行しません。すでに欠落したデータを修復する機能ではありません。
- 不完全な区間のエラーに区間番号・位置・サイズを表示します。
- `npx playwright install webkit` 後、`npm run test:webkit` でワーカーからの受信、保存、再読み込み、MP4出力、ZIPのCRCを検証できます。Windows版WebKitの試験であり、iPhone実機での確認は別途必要です。

## v0.4.2 画面の説明を整理

- 1440p・4K選択時に30fps制限の注意と、60fpsなら1080p以下を選ぶ案内を表示します。特定の端末名は表示しません。カメラへの要求値・録画処理は変更しません。
- カメラ・向き・fps診断・容量の詳細は「撮影のヒント・録画情報」に集約し、通常は折りたたみます。
- 保存画面は動画作成を主操作とし、元区間・復旧用ZIPは別の折りたたみに配置します。共有・ダウンロード・削除は引き続き利用できます。
