# ReplayCam PWA v0.2.1

Windowsで開発・公開できる、iPhone向けカメラ録画アプリの初版です。静的Webアプリ、サーバーへの動画送信なし。動画結合には同梱のMediabunnyを使用します。

## 実装済み

- 初期設定 **3分 / 1080p / 60fps / マイクON**（設定は端末に保存）
- リプレイバッファ **3・5・10・15分**。15秒ほどの独立した録画区間をIndexedDBへ保存し、古い区間を削除
- 保存ボタンで直前の録画区間を保存済み一覧へ登録。保存後も録画を継続
- リプレイ区間を個別再生・保存、または動画に結合 / ZIPファイルで一括書き出し
- 通常録画モード：停止時に1本のMP4/WebMとして保存、ダウンロード
- 720p / 1080p / 1440p / 4K（2160p）の希望設定、30/60fps、音声ON/OFF
- 内カメラ（前面）/ 外カメラ（背面）の選択と、実際の使用カメラの表示
- 希望設定から容量を予想し、録画中は実測したデータ量から補正
- リプレイの端末内自動結合と動画の直接ダウンロード（合計256MiBまで・画面上では256MBと表記）
- HTTPS上でPWAとしてインストール、初回読み込み後はオフライン起動を目指すService Worker
- 保存済み動画の一覧・削除・容量表示

## 重要な制限

- **iPhoneのSafariでの動作は未検証**。ブラウザによるカメラ許可、録画コーデック、保存/共有、IndexedDB容量は端末実機で検証してください。
- **4Kを含む選択した解像度・fpsを必ず達成するわけではありません。** ブラウザとiPhoneが許可する実効値はプレビュー右上に表示されます。実際のエンコードされた動画のfps/解像度はファイルでも確認してください。
- リプレイバッファは独立した15秒前後の動画ファイルを順次録画する実装です。「保存済み」から書き出す際、対応する区間を再圧縮せず1本のMP4/WebMに結合します。**合計256MiBを超える場合や、区間の形式・音声構成・画角が一致しない場合、結合に失敗した場合はZIPへ切り替えます。** メモリが不足してブラウザーが終了すると自動切り替えも完了できないことがありますが、元の区間は保存済みに残ります。 録画再起動時に短い欠落があり得ます。ZIPから取り出した動画をWindows PCの動画編集ソフト等で結合できます。録画した15分が完全に連続することは保証できません。
- 通常録画は同じMediaRecorderの複数 `dataavailable` データを正しい順で連結して1本のファイルにします（独立動画を単純結合していません）。
- SafariやiOSの制限により、画面ロック・アプリ切替・電源管理で録画が中断されることがあります。録画中は画面を開いたままにしてください。
- 15分1080p/60fpsは数百MB〜1GB超になる可能性があります。iOSストレージの容量制限、バックグラウンド停止、サイトデータ削除で未書き出し動画を失う可能性があります。**保存済み一覧への登録だけでは写真アプリへの保存にはなりません。必ず「書き出す」で端末の「ファイル」に保存してください。**
- サーバーは動画データを受信しません。HTTPSで配信する静的ファイル以外に通信を必要としません。
- 当初の設計からPCの遠隔操作機能は**未実装**。カメラの録画・保存の検証を優先しています。

## Windowsから無料でiPhoneに導入する

### GitHub Pagesで公開（HTTPS、無料）

1. GitHubに新しい**公開リポジトリ**（例: `replaycam`）を作ります。動画はGitHubには上げません。上げるのはこのZIPに含まれるHTML/CSS/JS等だけです。
2. ZIPを展開し、中にある `index.html`・`app.js`・`sw.js`・`manifest.webmanifest`・`icons/` などを **リポジトリのルート** にアップロードします。
3. リポジトリの `Settings` → `Pages` → `Build and deployment` → `Deploy from a branch` → `main` / `/(root)` → `Save`。
4. Pagesに表示される `https://ユーザー名.github.io/replaycam/` にiPhoneの **Safari** でアクセスします。
5. Safariの共有メニューから **ホーム画面に追加**。アプリアイコンから起動して録画できます。
6. 初回表示後、通信を切って再起動できるか試してください。オフライン時のカメラ権限動作も合わせて確認します。

> GitHub Pagesに公開するWebアプリのソースは公開されます。録画データ自体はiPhoneのローカルIndexedDB内に残り、GitHubにはアップロードされません。

### 開発テスト

```bash
node --test tests/*.test.mjs
python -m http.server 8000
```

Windows上で `http://localhost:8000` を開けば画面とPCカメラのテストができます。ただし、iPhoneからWindowsの `http://192.168.x.x:8000` にアクセスしても、通常はHTTPSではないためカメラが使えません。GitHub PagesなどのHTTPSが必要です。

## 操作

- 「リプレイバッファ」を選び「録画開始」→任意の時点で「直前を保存」→「保存済み」から「開く」→「結合して動画をDL」。明示的に「ZIPで保存」も選べます。
- 「通常録画」→「録画開始」→「終了して保存」→保存済み一覧から動画を1本で書き出します。
- ダウンロード操作で動画を保存します。自動ダウンロードが始まらない場合は書き出し後のリンクをタップしてください。Safariでプレビューが開く場合は共有メニューから「ファイルに保存」を選んでください。保存済み一覧は端末の写真ライブラリではありません。

## 次の開発予定

- iPhone実機でMediaRecorderのコーデック・分割保存・容量を検証
- 長時間・大容量の結合、録画区間の切り替え時の欠落の改善
- 長時間安定性、画面スリープ対策、空き容量不足の事前警告
- Windows PCのリモート画面表示・操作（別モジュール、認証/暗号化必須）

## Windowsでリプレイを1本に結合する

リプレイをZIPで書き出した後、Windows PCへ移して次の操作を行います。

1. Windowsに **FFmpeg** をインストールしてPATHを通す（初回のみ）。
2. ZIPファイルを `windows/merge_replay.bat` にドラッグ＆ドロップする。
3. 同じフォルダに結合した `.mp4` または `.webm` ファイルができます。

FFmpegの `concat` を利用して映像と音声を再エンコードせず結合します。分割録画時点の短い欠落は修復できません。コーデックやタイムスタンプの状態によっては結合できず、再エンコードが必要になる場合があります。

## v0.2.0 開発と検証

`npm ci` → `npm test`。同梱ライブラリの再生成は `npm run build:vendor`。`vendor/mediabunny.js` はMediabunny 1.65.2の固定版で、ライセンスは `vendor/mediabunny-LICENSE.txt`。実行時のCDNや動画アップロードはありません。

ブラウザーテストは `npm run test:browser`。既定はWindowsのBraveを専用のテストプロファイルで起動し、疑似カメラ・マイクを使用します。別のChromium系ブラウザーを使う場合は `REPLAYCAM_BROWSER` に実行ファイルのパスを指定します。iPhone Safari実機の検証を代替するものではありません。テスト動画はFFmpegのtestsrcとsineで生成した素材です。MP4/WebMの映像・音声・時刻・回転、無音動画、失敗時のZIP、設定保存、オフライン起動を検証します。

## サイトの共有

公開URLを他の人に共有できます。録画・保存・結合は各利用者のブラウザーで行い、利用者間で動画は共有されません。端末容量、カメラ権限、Safariの対応状況に依存する試用版として案内してください。サイトのデータを消去すると、未書き出し動画を失う可能性があります。

更新時はオンラインでページを再読み込みし、一度閉じて開き直してフッターがv0.2.0になったことを確認してください。既存の保存済み動画のデータベース構成は変更していません。

## v0.2.1 横向き録画

端末の画面回転ロックを解除し、横向きに持ってから「録画開始」を押してください。通常録画とリプレイバッファの両方に対応します。プレビューは映像全体を表示し、実際のカメラ映像の縦横比に追従します。横画面では録画・保存・停止ボタンを映像の横に配置します。

録画開始時の向きを保存済み一覧に表示します。録画中に画面の向き、またはカメラ映像の縦横が変わると、通常録画を保存して終了し、リプレイでは直前のバッファを保存して終了します。向きを合わせて録画を再開してください。端末やブラウザーが回転通知を提供しない場合は検知できないため、録画中は向きを保ってください。既存の保存済み動画や縦向き録画、動画の回転情報を保った結合処理は維持しています。

デスクトップブラウザーの疑似カメラによる横向き動画のダウンロード・音声・画面回転時の保存を自動テストしています。iPhone実機での回転、Safari固有の回転情報・撮影挙動は未検証です。更新後はページを再読み込みし、フッターのv0.2.1を確認してください。
